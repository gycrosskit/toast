## 环境与检查

源码构建使用 JDK 17、Gradle wrapper、Android SDK（compileSdk 36）；iOS 需要 macOS/Xcode，HarmonyOS HAR 需要匹配 API 22 的 DevEco SDK、ohpm 与 hvigorw。先配置 `ANDROID_HOME` 和 HarmonyOS 工具链路径，命令从仓库根目录运行；以下是维护者检查命令，不是第三方安装步骤。

```sh
bash gradlew :toast:compileDebugKotlinAndroid :toast:compileKotlinIosSimulatorArm64 :toast:compileKotlinOhosArm64 :toast-cmp:compileKotlinIosSimulatorArm64 :toast-kuikly:compileKotlinOhosArm64
bash gradlew :toast:iosSimulatorArm64Test
bash gradlew :androidApp:assembleDebug
xcodebuild -scheme GycToastNative -destination 'generic/platform=iOS Simulator' -sdk iphonesimulator CODE_SIGNING_ALLOWED=NO build
```

HarmonyOS HAR 在 `ohos/` 内执行：

```sh
ohpm install --all
hvigorw --mode module -p module=ToastNative@default -p product=default assembleHar --no-daemon
```

需要 SDK 的检查只在对应环境执行；不默认 `clean` 或全仓库构建。独立消费者使用 README 的远程 Maven 坐标，不使用 `mavenLocal` 或源码 `project/includeBuild` 替换。

## Maven 产物维护

0.1.3 候选在 macOS 用 `GROUP=com.github.gycrosskit.toast` 构建完整 core/CMP/Kuikly staging，归档前正规化并校验 metadata。JitPack 从不可变 Git tag 的 Release 下载固定 SHA-256 归档，校验后安装原字节，无消费端 Python。Swift/CocoaPods 和 HAR 版本分别由其 metadata 声明，不能从 Maven 成功推断原生发布或设备验收。

独立远程 consumer 不使用本地源码替换，候选发布后执行：

```sh
bash gradlew -p verification compileKotlinOhosArm64 -PtoastVersion=0.1.3 --max-workers=1 --no-parallel
bash gradlew -p verification compileDebugKotlinAndroid compileKotlinIosArm64 compileKotlinIosX64 linkDebugFrameworkIosSimulatorArm64 -PverifyCmp=true -PtoastVersion=0.1.3 --max-workers=1 --no-parallel
```

Android/iOS probes 同时引用 CMP CompositionLocal，OHOS probe 引用 ToastModule.show/dispose；三种 Maven 产品均需验证。

完整发布步骤与不可变产物约束见 [GY CrossKit 发布流程](https://github.com/gycrosskit/.github/blob/main/docs/发布流程.md)，历史版本见 [发行页](https://github.com/gycrosskit/toast/releases)。
