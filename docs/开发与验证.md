## 当前候选：移除 CMP

Maven / 原生 Git Pod / OHOS HAR `1.0.0` 为配套源码候选，尚未发布；Maven 只构建 `toast` / `toast-kuikly` 两个产品。KuiklyCompose/compiler/runtime 与 native 接线保留。以下先验证当前候选，其后带日期的结果是历史记录。

```sh
python3 tests/test_no_cmp.py
python3 tests/test_release_candidate.py
python3 tests/test_metadata.py
bash gradlew -I scripts/ci-repositories.gradle :toast:testDebugUnitTest :toast-kuikly:testDebugUnitTest :toast-kuikly:compileDebugKotlinAndroid --max-workers=1 --no-parallel
bash gradlew :toast:iosSimulatorArm64Test :toast-kuikly:compileKotlinIosSimulatorArm64 :toast-kuikly:compileKotlinOhosArm64 --max-workers=1 --no-parallel
```

独立 consumer 默认 `toastVersion=1.0.0`，默认仍解析远程 Maven。未发布候选显式使用 composite source substitution：

```sh
bash gradlew -p verification -PverifyLocalSource -PtoastVersion=1.0.0 compileDebugKotlinAndroid verifyNoCmpUi --max-workers=1 --no-parallel
```

此模式只替换本仓库 `toast` / `toast-kuikly`，没有 `mavenLocal`，输出 `local source=true`，不能证明公开 Maven 已发布。

源码验证的 Android 阶段先跑 core/Module 测试与编译，再显式启用 `verifyLocalSource` 编译当前候选 consumer 并执行 `verifyNoCmpUi`。这属于本地源码消费；精确已发布版本按[发布流程](https://github.com/gycrosskit/.github/blob/main/docs/发布流程.md)由独立 release Job 验证远程 Maven。

若要独立检查候选 Maven metadata，可先构建本地 staging：

```sh
GROUP=com.github.gycrosskit.toast VERSION=1.0.0 bash gradlew publishAllPublicationsToStagingRepository --max-workers=1 --no-parallel
python3 scripts/jitpack-metadata.py build/maven/com/github/gycrosskit/toast
python3 scripts/check-maven.py build/maven com.github.gycrosskit.toast 1.0.0 toast,toast-kuikly ios_arm64,ios_x64,ios_simulator_arm64,ohos_arm64
bash gradlew -p verification -PtoastMavenRepo="file://$PWD/build/maven" -PtoastVersion=1.0.0 compileDebugKotlinAndroid verifyNoCmpUi --max-workers=1 --no-parallel
```

`verifyNoCmpUi` 先拒绝任何未解析的 runtime dependency，再检查真实 Android runtime graph：允许 KuiklyCompose/runtime，拒绝第二套 JetBrains/AndroidX UI、foundation、material 与已移除的 CMP 产品。Python 合同只检查源码/配置与真实 metadata checker 的输入输出，不能代替此解析或实际 UI 运行。`toastMavenRepo` 的本地消费不代表 JitPack 已可用。

本轮远程归档入口为 `VERSION=1.0.0 bash scripts/package-maven.sh`，生成 `build/toast-maven.tar.gz` 与真实 `.sha256`；新归档严格检查 12 个 publication 和所有四类 sidecar。精确 Release consumer 使用 `-PremoteOnly` 强制从 JitPack 消费，Git Pod 独立固定 `1.0.0` 并核对 tag / Pod 版本 / SHA / 安装 Swift 字节。

发布后以精确新版本运行 Release CI，远程 consumer 使用公开 Maven；原生 consumer 仍需真实 Renderer 链接。当前脚本只接受两产品合同；重验 `0.1.x` 的三产品旧归档时，检出对应 tag 使用原脚本/consumer。旧 tag、checksums 与下方历史验收不改写。

## 环境与检查

源码构建使用 JDK 17、Gradle wrapper、Android SDK（compileSdk 36）；iOS 需要 macOS/Xcode，HarmonyOS HAR 需要匹配 API 22 的 DevEco SDK、ohpm 与 hvigorw。先配置 `ANDROID_HOME` 和 HarmonyOS 工具链路径，命令从仓库根目录运行；以下是维护者检查命令，不是第三方安装步骤。

```sh
bash gradlew :toast:compileDebugKotlinAndroid :toast:compileKotlinIosSimulatorArm64 :toast:compileKotlinOhosArm64 :toast-kuikly:compileKotlinOhosArm64
bash gradlew :toast:iosSimulatorArm64Test
bash gradlew :androidApp:assembleDebug
xcodebuild -scheme GycToastNative -destination 'generic/platform=iOS Simulator' -sdk iphonesimulator CODE_SIGNING_ALLOWED=NO build
```

HarmonyOS HAR 在 `ohos/` 内执行：

```sh
ohpm install --all
hvigorw --mode module -p module=ToastNative@default -p product=default assembleHar --no-daemon
```

需要 SDK 的检查只在对应环境执行；不默认 `clean` 或全仓库构建。远程验收使用 README 的远程 Maven 坐标，不传 `verifyLocalSource` 或 `toastMavenRepo`，不使用 `mavenLocal`；显式本地候选模式见上方。

## 源码 CI 编译缓存

以下为历史 Actions 缓存配置，仅用于原 tag/旧运行核对；当前源码 verify 的缓存与执行参数以[统一远程验证（Jenkins）](https://github.com/gycrosskit/.github/blob/main/docs/统一远程验证.md)及固定版本 recipe 为准。

源码 `android/native` jobs 使用固定 SHA 的 `gradle/actions/setup-gradle` 复用 Gradle User Home，并通过现有 init script 启用编译缓存。PR 只读缓存，完整源码 dispatch 与 main 可写入当前 ref 的缓存；源码修改仍由 Gradle 输入指纹决定是否重编译。仅工具链预热不恢复或保存此 Gradle 缓存，避免先占用同 SHA 的不可变 key 而阻止后续源码结果写入。

`AbstractTestTask` 禁用缓存及 up-to-date 跳过，行为测试每次实际执行；原编译目标、Simulator/Swift 检查、链接、超时与门禁保持不变。发布 jobs 不启用本策略，保留原精确版本及依赖刷新验证。冷暖耗时必须绑定同一 SHA 与完整源码运行，不能把缓存预热或普通 main push 的轻量检查算作源码通过。
