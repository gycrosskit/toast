# 功能与平台差异

核对日期：2026-10-08。固定Git基线：`f43b4fb901b93358731f6df65fa5bc680dd4730c`。正式源码0.1.5；本轮仅文档候选，没有代码或版本变更。原生OHOS HAR仍按独立版本消费。

组件提供宿主已本地化的短消息展示。优先区分应用内 `MessageHost` Overlay 与 legacy 系统/原生 presenter：前者在 CMP Android/iOS、KuiklyCompose Android/iOS/OHOS 消费共同状态与规格；后者受 Android Toast、UIKit UIWindow、OHOS PromptAction 控制。两种路径均可使用，视觉与生命周期合同不能混称完全一致。

## 公开功能与合同

- `MessagePlatform.show(message, AppMessageDuration)` 在trim后忽略空白，`show(message)`默认SHORT。Overlay精确SHORT=2000ms、LONG=3500ms；legacy原生路径只消费时长档位，实际时长受系统/presenter控制。
- `MessageOverlayState` 使用requestId替换旧消息；迟到dismiss不能移除新消息，`dispose`为终态。两套Host的timer均按state/requestId归属，宿主负责正确挂载Host与释放state。
- `ProvideMessagePlatform`/`LocalMessagePlatform`/`rememberMessages` 注入宿主实例，缺少provider明确抛错，不隐式使用全局fallback。
- Overlay共同规格：outerPadding16、horizontal18、vertical12、corner12、maxWidth520、fontSize14、lineHeight20，背景D6000000、文本FFFFFFFF，polite liveRegion。Kuikly背景/padding用独立Box以适配其Text布局；这些源码参数一致不代表字体/多行/朗读已通过设备验收。
- legacy `ToastModule.show`是无回调异步转发；dispose阻止新转发，已显示消息归共享native presenter管理。Swift需稳定rootController绑定；OHOS需原生Module注册及UIAbilityContext。

## 差异分类与使用边界

| 分类 | 当前合同与限制 |
| --- | --- |
| 组件入口 | CMP和KuiklyCompose均有Overlay provider/Host；legacy native presenter仍保留。不能只调用legacy show后按Overlay规格验收。 |
| OS/SDK边界 | 原生AndroidToast/UIKit/OHOS提示视觉与时长受系统/原生实现约束；Kuikly Text布局需Box背景/padding。 |
| 宿主输入 | 文案/语言由宿主提供，缺provider明确失败；native桥、rootController、OHOS注册/context与释放归属必须正确。 |
| 未验收 | 五入口实际字体倍率、长多行、深浅色/居中、屏幕朗读与真实OHOSPromptAction时序未本轮设备验收；共同Spec/状态机与编译不能替代。 |
