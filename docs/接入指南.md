# Toast 接入指南

[返回README](../README.md) · [功能与平台差异](功能与平台差异.md)

本页描述 0.1.6 接收端候选，发布与远程消费以 Release 结果为准；OHOS 原生 HAR 保持 0.1.3。共同应用内Overlay与legacy系统提示是两条路径。优先在页面根部使用对应包 `MessageHost(MessageOverlayState) { ... }`，它自动提供平台；CMP包为 `io.github.gycrosskit.toast.cmp`，KuiklyCompose包为 `io.github.gycrosskit.toast.kuikly`，后者覆盖A/i/O。每个Host独占state，移除为终态，重建页面需新实例。下列AndroidMessagePlatform/Swift presenter/ToastModule说明属于legacy接入，不能当共同Overlay视觉合同。

## Gradle 与工具链

根 README 列出远程安装坐标。本库 KMP 产物使用 Kotlin `2.2.21-1.0.0`；OHOS target 必须使用兼容的厂商工具链。项目构建使用 Gradle `8.11.1`、AGP `8.10.1`、Android compileSdk `36`，Gradle 运行使用 JDK 17。源码的 Java/JVM 编译目标与运行 Gradle 的 JDK 是不同要求。

在 `settings.gradle.kts` 中为 Kotlin 插件与依赖分别配置仓库；保留宿主已有仓库：

```kotlin
pluginManagement {
    repositories {
        maven("https://maven.eazytec-cloud.com/nexus/repository/maven-public/")
        google()
        mavenCentral()
        gradlePluginPortal()
    }
}
dependencyResolutionManagement {
    repositories {
        maven("https://jitpack.io")
        maven("https://maven.eazytec-cloud.com/nexus/repository/maven-public/")
        google()
        mavenCentral()
        maven("https://mirrors.tencent.com/nexus/repository/maven-public/")
        maven("https://mirrors.tencent.com/nexus/repository/maven-tencent/")
    }
}
```

Kuikly 模块使用 `2.28.0-2.0.21-ohos`。Swift Package、OHPM HAR 和 Maven KLIB/AAR 分别安装，Maven 不替代原生依赖或宿主桥接。HarmonyOS 包的 `targetSdkVersion` 和 `compatibleSdkVersion` 均为 `6.0.2(22)`，不据接口 API 级别推断当前 HAR 可运行于更低系统。

## Android 与 CMP

Android 使用 `AndroidMessagePlatform.get(applicationContext)`；CMP、Kuikly 等入口复用同一实例。直接 `show(message)` 使用短时长，显式 `show(message, AppMessageDuration.LONG)` 使用长时长。文案先完成本地化，空白文案忽略。

CMP 根部调用 `ProvideMessagePlatform(platform) { ... }`，子页面使用 `rememberMessages()`。未提供 platform 会抛出错误，不使用隐式全局 fallback。`toast-cmp` 只支持 Android/iOS，OHOS 使用 `toast-kuikly`。

## Android/iOS Native Module

`ToastModule` 的三端客户端保持名称 `GycToastModule`、`show` 参数 `message/duration` 和无结果回调合同。Android/iOS 原生接收端从 0.1.6 候选补齐；旧 0.1.5 虽有三端客户端，不能据此认定端到端接通。

Android 在当前 Renderer 的 `registerExternalModule` 中装配：

```kotlin
import io.github.gycrosskit.toast.kuikly.registerToastModule
// this 为 IKuiklyRenderExport；每个 Renderer 注册一次。
registerToastModule(context)
```

接收端复用 `AndroidMessagePlatform.get(context)`，与 CMP 使用同一进程提示入口。`onDestroy` 丢弃尚未显示的排队调用，不关闭其他 Renderer 已显示的进程提示。

iOS 使用 Git Pod 的可选 subspec（SPM 当前仅提供 Core presenter）：

```ruby
pod 'GycToastNative/Kuikly', :git => 'https://github.com/gycrosskit/toast.git', :tag => '0.1.6'
```

```swift
import GycToastNative
GycToastPresenter.shared.bind(rootController: stableRootController)
GycToastModule.register() // 创建 Renderer 前显式引用正确的 Objective-C 类型。
```

SDK 按 `@objc(GycToastModule)` 创建当前 Renderer 的接收端。接收端只在 Main 调用已有 presenter；`invalidate` 后丢弃排队任务，不新增 Kotlin framework 或 SDK runtime。SDK 依赖固定 `OpenKuiklyIOSRender 2.28.0`。宿主无需复制 JSON 解析或 transport。

## iOS Swift Package / CocoaPods

Swift Package Git URL、版本与产品见 README。CocoaPods 使用 Git tag，无需假定它已发布到 CocoaPods trunk：

```ruby
pod 'GycToastNative', :git => 'https://github.com/gycrosskit/toast.git', :tag => '0.1.5'
```

稳定的根 UIViewController 创建后 `GycToastPresenter.shared.bind(rootController:)`；随后 `show(message:longDuration:)`。原生 presenter 使用独立不可点击 UIWindow，避免依附临时 dialog window。

KMP 宿主导出 core API 到自己的 Framework，Swift 实现 `IosMessageBridge.showMessage(message:longDuration:)`，转发 `GycToastPresenter.shared.show(message:longDuration:)`，再将 bridge 交给 `IosMessagePlatform(bridge)`。Framework 名称由宿主决定。

## HarmonyOS 原生 / Kuikly

已创建主窗口的 UIAbility 中调用：

```typescript
import { GycToastPresenter, GycToastModule } from '@gycrosskit/toast-native';
GycToastPresenter.shared.show(context, '操作完成');
// Kuikly render 的模块注册表：
modules.set(GycToastModule.MODULE_NAME, () => new GycToastModule());
```

`context` 为 `UIAbilityContext`，`modules` 为宿主 render 的模块注册表。Kotlin Pager 注册 `ToastModule.NAME to ToastModule()`（包 `io.github.gycrosskit.toast.kuikly`）；Module 本身实现 `MessagePlatform`，名称为 `GycToastModule`。

`PromptAction.openToast/closeToast` 接口从 API 18 起提供，当前打包工程声明 compatible SDK 为 API 22；需在当前 HAR 支持的系统上消费。原生 presenter 串行 open/close，新消息替换旧消息，迟到的旧 open 结果会被关闭，不提供消息队列或交互能力。
